Разработчики устранили критическую ошибку в фреймворке Smolagents

Исправлена ошибка в популярном фреймворке Smolagents, которая затрагивала пользователей, комбинирующих инструменты MCP с сериализацией агентов. Ошибка, существовавшая с ноября 2023 года, приводила к сбою при попытке сериализации агента, содержащего инструменты MCP. Разработчики использовали Sentry для отслеживания и диагностики проблемы, успешно устранив её. Это исправление важно для стабильности работы агентов, использующих протокол MCP для взаимодействия с внешними инструментами.

2 независимых источника 07:37
История, контекст и источники ⌄

Расширенный контекст

Фреймворк Smolagents, получивший более 28 тысяч звезд на GitHub, позволяет агентам выполнять действия, написанные на Python. Одной из проблем, с которой сталкивались разработчики, была ошибка, возникающая при попытке сериализовать объект `CodeAgent`, который содержит инструменты, реализованные с использованием протокола Model Context Protocol (MCP). Протокол MCP позволяет клиентским приложениям, таким как Claude Desktop, вызывать инструменты, предоставляемые сервером, что упрощает взаимодействие с внешними сервисами и структурированное хранение данных. Ошибка, идентифицированная как issue #1108, проявлялась при вызове методов `agent.to_dict()`, `save()` или `push_to_hub()`, приводя к исключению `ValueError: Tool validation failed for MCPAdaptTool: Parameters in __init__ must have default val`. Эта проблема затрагивала всех пользователей, которые использовали одновременно возможности MCP и сериализацию агентов.

Устранение данной ошибки критически важно для разработчиков, использующих фреймворк Smolagents в сочетании с протоколом MCP. Ошибка препятствовала нормальной работе с агентами, особенно в сценариях, требующих сохранения или передачи состояния агента, например, при работе с персональными финансовыми трекерами, где необходимо логировать транзакции через естественный язык. Стабильная работа механизма сериализации обеспечивает надежность приложений, построенных на Smolagents, и позволяет избежать потери данных или сбоев в работе AI-ассистентов, интегрированных с внешними инструментами через MCP.

Resk-LLM: Новый инструмент для защиты Python LLM от уязвимостей

Представлен Resk-LLM, новый открытый инструментарий на Python, который объединяет 11 детекторов угроз в одном промежуточном ПО FastAPI. Этот инструмент предназначен для защиты конвейеров больших языковых моделей (LLM) от распространенных атак, таких как внедрение подсказок (prompt injection) и обход ограничений (jailbreak). Resk-LLM предлагает решение для обеспечения безопасности LLM, которое отличается высокой скоростью и доступностью, в отличие от проприетарных API или медленных защитных механизмов. Инструмент легко интегрируется в существующие приложения FastAPI, предоставляя мгновенную защиту от широкого спектра угроз, включая утечку персональных данных (PII), внедрение кода и эксфильтрацию данных.
