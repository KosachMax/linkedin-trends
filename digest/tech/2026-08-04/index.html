Команда разработчиков Django выпустила обновления безопасности для версий 6.0.8 и 5.2.17. Эти релизы устраняют уязвимость CVE-2026-15307, связанную с записью файлов на стороне сервера и подделкой запросов через пространственные запросы (spatial lookups). Уязвимость позволяла передавать значения поиска строк и словарей в GDALRaster, что могло привести к записи файла на диск (в некоторых случаях с возможностью удаленного выполнения кода) или отправке сетевого запроса от имени пользователя процесса Django. Разработчики настоятельно рекомендуют всем пользователям Django как можно скорее обновить свои системы.

Расширенный контекст

Команда разработчиков фреймворка Django объявила о выпуске обновлений безопасности для двух веток проекта: Django 6.0.8 и Django 5.2.17. Эти обновления направлены на устранение критической уязвимости, обозначенной как CVE-2026-15307. Проблема связана с функцией пространственных запросов (spatial lookups), которая при определенных условиях позволяла злоумышленникам использовать уязвимость для записи произвольных файлов на сервер. В зависимости от конфигурации и используемых драйверов, это могло привести к полному компрометированию сервера через удаленное выполнение кода. Кроме того, уязвимость могла быть использована для отправки сетевых запросов от имени пользователя, от которого запущен процесс Django. Разработчики подчеркивают важность своевременного обновления для всех пользователей фреймворка.

Уязвимость CVE-2026-15307 в Django представляет серьезную угрозу безопасности, поскольку она может позволить злоумышленникам получить полный контроль над сервером, на котором работает приложение, написанное с использованием этого фреймворка. Возможность удаленного выполнения кода (RCE) и подделки запросов открывает двери для кражи данных, нарушения работы сервисов и дальнейшего распространения вредоносного ПО. Своевременное применение обновлений безопасности является критически важным шагом для защиты веб-приложений от потенциальных атак и обеспечения конфиденциальности пользовательских данных.

Расширенный контекст

В период с января по июнь 2026 года команда SQLAlchemy активно работала над развитием версии 2.1.0, выпустив три бета-версии: 2.1.0b1, 2.1.0b2 и 2.1.0b3. Каждая из этих версий принесла с собой ряд значительных изменений и улучшений. В частности, версия 2.1.0b1 добавила поддержку свободных потоков Python в колесах, распространяемых через PyPI, что является частью более широкой работы по улучшению поддержки многопоточности в сериях 2.0 и 2.1. Также было принято решение отказаться от автоматической установки зависимости greenlet для поддержки asyncio, поскольку она не требуется для всех приложений и не имеет колес для всех архитектур. Версия 2.1.0b2 представила новые возможности для SQL, включая параметр _sql.over.exclude, позволяющий использовать стандартные для SQL конструкции исключения фреймов в оконных функциях.
