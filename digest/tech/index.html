Технологии · Новое 6,0

Разработчик столкнулся с проблемой производительности своего ИИ-агента, построенного на FastAPI и использующего модель gpt-4o-mini от OpenAI. Агент выполнял пять последовательных вызовов LLM для обработки одного запроса, что приводило к задержкам, которые сложно было диагностировать с помощью стандартных HTTP-логов. Для решения этой проблемы была внедрена система трассировки SigNoz, установленная в среде WSL 2 на Windows. Это позволило детально анализировать каждый шаг выполнения запроса, включая время, затраченное на каждый вызов LLM, и количество использованных токенов, а также выявлять возможности для параллельного выполнения задач.

Расширенный контекст

Разработчик создал ИИ-агента, который получает тему, разбивает ее на три подвопроса с помощью LLM, отвечает на каждый подвопрос отдельным вызовом LLM, а затем объединяет ответы в краткое резюме с помощью еще одного вызова LLM. В общей сложности для обработки одного запроса выполняется пять вызовов LLM. Хотя агент всегда возвращал осмысленный результат, стандартные HTTP-логи показывали только общее время выполнения запроса (около десяти секунд), но не давали информации о том, какой из пяти вызовов LLM занимал больше всего времени, сколько токенов было использовано каждым из них, и могли ли они выполняться параллельно. Для решения этой проблемы была внедрена система трассировки SigNoz, установленная в среде Windows с использованием WSL 2 (Ubuntu). Это позволило детально отслеживать выполнение каждого шага внутри одного запроса.

Детальная трассировка выполнения запросов, особенно в сложных системах, использующих несколько вызовов LLM, критически важна для оптимизации производительности и снижения затрат. Инструменты вроде SigNoz позволяют разработчикам выявлять узкие места, такие как длительные последовательные вызовы LLM, и находить возможности для их параллелизации или оптимизации. Это приводит к ускорению ответа агента, снижению потребления ресурсов и, в конечном итоге, к улучшению пользовательского опыта. Кроме того, возможность отслеживать использование токенов помогает контролировать расходы на API LLM. Бен О'Мэхони также обсуждал создание пользовательских языковых серверных протоколов (LSP) на основе ИИ, которые используют телеметрию для улучшения моделей, что подчеркивает растущую важность мониторинга и анализа поведения ИИ-систем в производственной среде.
